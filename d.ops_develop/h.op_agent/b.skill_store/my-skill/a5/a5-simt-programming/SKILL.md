# A5 SIMT 编程与 SIMD/SIMT 混合编程

面向昇腾 **A5（Ascend 950PR / 950DT）** 的 SIMT 编程选型指导。

## 背景：A5 为什么引入 SIMT

上一代（如 Ascend910B）向量计算是纯 SIMD 模型。纯 SIMD 在**复杂控制流、离散访存**等场景下编程灵活性差。

Ascend 950PR / 950DT 在向量计算单元 **SIMD 基础上引入 SIMT 能力**，确立「SIMD 为主、SIMT 为辅」的新同构编程模型：

- 矩阵计算和向量计算中的 SIMD 部分，配了**超过 90% 的算力**，服务密集计算
- 向量计算中的 SIMT 作为**灵活性补充**，专门应对复杂控制流、离散访存等不规则场景

## SIMT 适用场景（决策标准）

遇到以下特征，优先考虑 SIMT 或 SIMD/SIMT 混合：

1. **复杂控制流**：核函数里有大量分支（if/else）、不规则循环
2. **离散访存**：数据不是连续块，而是稀疏、索引跳变的访问模式
3. **标量化逻辑**：逻辑里以标量计算为主、而非规整的向量化运算

反之，以下情况应继续用 SIMD：

- 规整的连续数据搬运与计算
- 密集的向量/矩阵运算（这是 SIMD 的主场，占了 90%+ 算力）

## SIMD 与 SIMT 的关键差异（对编程的影响）

| | SIMD | SIMT |
|---|---|---|
| 编程抽象 | 单指令多数据，Tensor 编程为主 | 单指令多线程，贴近 CUDA 式线程模型 |
| 数据搬入 | 显式调用数据搬运 API（需插入同步） | 指针直接访问 Device Memory，硬件自动加载到寄存器 |
| 数据搬出 | 显式调用数据搬运 API 写回 | 指针直接写回，无需显式搬运 API |
| 控制流 | 受限 | 支持分支、循环等标量代码 |
| 多线程 | — | 多线程协作需插入同步指令 |

## Ascend C 的 API 分层（与 SIMT 相关）

Ascend C 针对 A5 提供了多级 API，其中与 SIMT 直接相关：

- **SIMT API**：对标业界，提供单指令多线程 API；支持两种编程模型：
  - SIMT 编程
  - SIMD 与 SIMT 混合编程
- **AI CPU API**：作为补充，承担非矩阵类、逻辑比较复杂的分支密集型计算
- 语言扩展层 C API：Ascend 950PR/950DT 新增 SIMT、SIMD/SIMT 混合编程能力

> 具体 API 签名与列表请查官方「Ascend C API 列表」，本 skill 不罗列具体 API，避免版本间签名差异导致误导。

## 选型流程

1. 分析算子：数据是否规整？访存是否连续？分支是否密集？
2. 密集规整 → **SIMD**（主力，性能最高）
3. 存在复杂控制流/离散访存 → **SIMT 或 SIMD/SIMT 混合**
4. 非矩阵、分支极密集的逻辑 → 可考虑 **AI CPU**
